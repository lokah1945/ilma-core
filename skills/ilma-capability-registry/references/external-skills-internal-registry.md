## External Capability Entry Structure

```python
# Generated by bridge, converted in ilma.py boot:
CapabilityEntry(
    name="ext_plan-writing",              # ext_ prefix
    category=CapabilityCategory.COGNITIVE, # mapped from external category
    status=CapabilityStatus.PROVISIONAL,   # risk-based: safe→VERIFIED, critical→PROVISIONAL
    description="Structured task planning...",
    primary_tool="external_skill:plan-writing",
    fallback_tools=[],
```

## Routing External Capabilities

```python
from ilma_capability_registry import route_capability, is_capable

# Direct routing
success, tool = route_capability('ext_plan-writing')
# → success=True, tool='external_skill:plan-writing'

# Check if usable
is_capable('ext_plan-writing')  # → True (PROVISIONAL counts as usable)

# Fallback chain (currently empty for external skills)
from ilma_capability_registry import get_registry
reg = get_registry()
reg.get_fallback('ext_plan-writing')  # → None (no fallback_tools populated)
```

## Risk-Based Status Mapping (from ilma.py boot)

| External Risk | Internal Status | Auto-Registered |
|---------------|-----------------|-----------------|
| `safe` | `VERIFIED` | ✅ Yes |
| `critical` | `PROVISIONAL` | ✅ Yes |
| `high` | `PROVISIONAL` | ✅ Yes |
| `medium` | `PROVISIONAL` | ✅ Yes |
| `low` | `VERIFIED` | ✅ Yes |
| `none` | `PROVISIONAL` | ✅ Yes |
| `unknown` | `PROVISIONAL` | ✅ Yes |
| `offensive` | — | ❌ Blocked at bridge load |

**Note:** All non-offensive skills are currently auto-registered. Consider filtering to `safe` only for production.
